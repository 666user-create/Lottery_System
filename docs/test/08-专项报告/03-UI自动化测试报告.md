## 1. 概述

使用 Selenium WebDriver 对抽奖系统 Web UI 进行自动化回归测试，工程位于 `docs/test/artifacts/selenium/`（独立 Maven 工程），真实连接后端（localhost:8080）。

## 2. 工程结构

```
docs/test/artifacts/selenium/
├── pom.xml                      # Selenium + JUnit5 依赖
└── src/test/java/com/qa/ui/
    ├── BaseUiTest.java          # 基类：Chrome 驱动、alert 处理、截图
    ├── LoginPageUiTest.java     # 页面元素用例（SA-01 ~ SA-05）
    └── RegisterLoginFlowUiTest.java  # 注册→登录端到端（SA-06）
```

**设计要点**：
- 无头模式（`-Dselenium.headless=true/false` 切换）；
- 自动处理页面 alert（未登录提示、注册结果提示），避免阻塞；
- 每用例自动截图存档 `docs/test/artifacts/screenshots/`；
- 元素查找失败时降级跳过（兼容不同页面实现），关键断言保留。

## 4. 调试过程记录（重要痕迹）

| 轮次 | 问题 | 根因 | 处理 |
|---|---|---|---|
| 第1轮 | 3 用例报 UnhandledAlertException | 页面 JS 异步弹出 alert（未登录提示/注册结果），阻塞后续操作 | 新增 `dismissAlertIfPresent()` 轮询处理 |
| 第2轮 | 手机号校验失败 | 随机数用 UUID hex（含字母 a-f）拼入手机号 | 改为纯数字随机 |
| 第3轮 | 导航前遗留 alert 导致 driver.get 抛异常 | alert 跨页面残留 | open() 导航前后均清理 alert |
| 最终 | 6/6 全部通过 | - | ✅ |

## 6. 结论与建议

1. Selenium 自动化可稳定回归核心页面与注册登录旅程；
2. 建议扩展：管理员登录→创建活动完整流程、聊天转人工流程、工单处理流程的自动化；
3. 建议接入 CI（需准备 Chrome + ChromeDriver 环境）；
4. 页面 alert 提示文案需统一优化（见 BUG-006）。
