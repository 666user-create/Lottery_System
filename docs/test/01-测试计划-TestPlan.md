## 2. 测试目标

1. **功能正确性**：验证用户、活动、奖品、抽奖、AI 客服、FAQ、交接班七大业务模块的功能实现与需求一致。
2. **接口规范性**：验证全部 REST 接口的入参校验、返回格式（`CommonResult` 统一结构）、错误码语义正确。
3. **权限安全性**：验证登录鉴权（JWT）、管理员接口权限隔离（401/403）、注册身份策略有效。
4. **质量指标达成**：功能测试用例执行通过率 ≥ 95%；发现的所有 P1/P2 缺陷清零；P3/P4 缺陷有明确处理计划。
5. **自动化能力建设**：交付可运行的 pytest 接口自动化与 Selenium UI 自动化脚本，支持后续回归。

## 3. 测试范围

### 3.1 测试对象（本次版本）

| 模块 | 主要功能点 | 接口 |
|---|---|---|
| 用户模块 | 注册（普通/管理员）、密码登录、短信验证码登录、验证码发送、用户列表查询、当前用户信息 | `/user/*`（6 个） |

| 抽奖模块 | 发起抽奖（MQ 异步）、中奖记录查询（活动/奖品维度）、我的中奖记录、状态流转（责任链） | `/draw/*`（3 个） |
| AI 客服 | 工具调用聊天（SSE）、RAG 知识库聊天（SSE）、同步聊天 | `/api/chat/*`、`/api/ai/chat/*`（4 个） |
| FAQ 知识库 | 新增（自动生成向量）、删除、分页查询 | `/api/faq/*`（3 个） |
| 交接班工单 | 用户主动转人工、工单列表（按状态）、工单处理（改状态+备注） | `/api/handover/*`（3 个） |
| 公共组件 | Redis 缓存、JWT 签发/解析、手机号/邮箱加密存储、短信发送、邮件通知、验证码 | 组件级 |

### 3.2 不在本次测试范围

| 项目 | 原因 |
|---|---|
| RabbitMQ 集群高可用/压力测试 | 测试环境无法连接公司 MQ 服务器（8.136.222.102 不可达） |
| 真实短信/邮件外发链路 | 依赖第三方服务（阿里云/短信宝/QQ邮箱），使用沙箱或模拟验证 |
| 真实 DeepSeek/Embedding API 计费调用 | 涉及外部 API 成本，使用 mock 或兜底路径验证 |
| 移动端适配 | 无移动端需求 |
| 浏览器兼容性矩阵 | 本次仅覆盖 Chrome/Edge（与本机可用浏览器一致） |

## 4. 测试策略

### 4.1 测试金字塔

```
           / 少量 \
          /  手工  \    ← 手动 Web UI（端到端，关键场景）
         /   UI 测试 \
        /============= \
       /  Selenium UI  \ ← Web UI 自动化（回归）
      /    自动化回归    \
     /====================\
    /  Postman 接口测试    \ ← 接口功能/权限验证
   /  pytest+requests    \ ← 接口自动化回归
  /==========================\
 /  JUnit 单元/集成测试(现有)  \ ← 已有 11 个测试类
/==============================\
```

### 4.2 各测试类型策略

| 测试类型 | 工具 | 策略 | 执行方式 |
|---|---|---|---|
| 手动 Web UI | 浏览器（Chrome/Edge） | 覆盖 P0/P1 关键用户旅程：注册→登录→建活动→配奖品→抽奖→AI客服→工单 | 真实执行，记录截图与痕迹 |
| Web UI 自动化 | Selenium WebDriver + Java | 核心 5 条旅程脚本化，可重复回归 | 真实执行 |
| 接口功能测试 | Postman / curl | 全部接口：正向、反向、边界、权限矩阵 | 真实执行（curl） |
| 接口自动化 | **Python + pytest + requests** | 152 条用例，断业务码与数据正确性，可纳入 CI | 真实执行（151 passed / 1 xfailed） |
| 性能测试 | **JMeter 5.6.3 命令行** | 登录/活动列表/中奖记录 3 场景（3500 请求），产出 result.jtl + HTML Dashboard | 真实执行（0 错误 / 175.6 次每秒） |
| 安全测试 | 手动 + 脚本 | 越权、注入（SQL/提示词）、密钥泄露审查、暴力枚举 | 部分真实执行 |

### 4.3 测试数据策略

| 数据类型 | 来源 | 处理 |
|---|---|---|
| 基础数据 | 现有库（14 用户/5 活动/5 奖品/2 FAQ） | 只读复用，用于列表/详情/查询类用例 |
| 新建数据 | 测试执行时创建（如测试用户、测试活动） | 用例执行后清理或标记 `QA_` 前缀 |
| 加密数据 | 手机号经 `Encrypt` 加密存储 | 验证查询时解密一致 |
| 缓存数据 | Redis（活动详情、中奖记录、验证码、AI 记忆） | 执行前后清理相关 key，避免脏数据 |

### 4.4 准入准出标准

**准入标准（进入测试执行）**
1. 代码编译通过（`mvn compile` exit 0）；
2. 应用可启动，登录页可访问；
3. 冒烟测试用例（P0）全部通过；
4. 测试环境（MySQL/Redis）可用。

**准出标准（版本可发布）**
1. 测试计划内用例 100% 执行完毕；
2. P0/P1 缺陷关闭率 100%，P2 缺陷关闭率 ≥ 95%；
3. 接口自动化测试通过率 ≥ 95%；
4. 无遗留 P1 级未解决问题；
5. 测试总结报告评审通过。

## 8. 风险与应对

| # | 风险 | 概率 | 影响 | 应对措施 |
|---|---|---|---|---|
| 1 | RabbitMQ 不可达，抽奖 MQ 链路无法端到端验证 | 高 | 高 | 验证发送端（消息成功入队）；消费端逻辑用单元测试/代码审查兜底；缺陷报告中标注 |
| 2 | 外部短信/邮件/AI API 不可用 | 中 | 中 | 用验证码本地逻辑、日志、兜底路径验证；不依赖真实外发 |
| 3 | 测试数据污染（重复手机号/邮箱） | 中 | 中 | 使用时间戳生成唯一测试账号；执行后清理 |
| 4 | 性能测试已执行（JMeter 5.6.3），风险转为「未覆盖抽奖写接口（依赖 MQ）」 | 高 | 中 | 已在 08-专项报告-02 记录真实数据；MQ 就绪后补测抽奖链路 |
| 5 | 应用启动受 RabbitMQ 连接超时拖慢 | 高 | 低 | 已知现象，等待超时后继续；启动成功判定以 8080 端口为准 |
