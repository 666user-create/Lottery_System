## 2. 已修复缺陷详情（含回归验证）

### BUG-002（P2，已修复）前端成功码误判导致 3 处功能完全不可用

| 项 | 内容 |
|---|---|
| 现象（原描述） | 「注册页无 token 加载弹错误提示」 |
| **实测纠正** | Selenium 逐页取证：`user-register.html` 加载时**无弹窗**；真正问题在 `admin-handover.html` / `chat.html`。且实际文案是「加载失败」而非「注册失败」（原记录为转录笔误） |
| 根因 | 前端写 `if (res.code !== 0)`，而本项目成功码为 **200**（`CommonResult.success`）→ **把成功当失败** |
| 影响面（3 处） | `admin-handover.html:56` 工单列表永远空白；`:91` 工单处理（处理中/已解决）永远失败；`chat.html:133` 用户端转人工按钮永远失败 |
| 附加问题 | `admin-handover.html` 无 token 时 alert 后**不中断流程**，`loadList()` 仍执行 → 连弹 2 个弹窗 |
| 修复 | 成功码 3 处改为 `!== 200`；未登录改为 `location.assign('admin-login.html')` 并加 `if (token)` 守卫 |
| 验证（Selenium 实测，4 场景） | S1 无token：1 弹窗 + 跳转 ✅；S2 有token：**0 弹窗 + 表格渲染 1 行** ✅；S3 工单处理：提示「已更新」✅；S4 转人工：无失败弹窗 ✅ |
| 防退化用例 | `test_14::TestBug002FrontendSuccessCode`（3 条静态检查，可抓同类回归） |
| **教训** | 第③步 Selenium 用例只断「元素存在」未断「功能可用」，故漏检此缺陷 → 已补充静态检查与功能验证 |

### BUG-003（P3）邮箱校验拒绝大写字母

| 项 | 内容 |
|---|---|
| 现象 | 含大写字母的合法邮箱（如 `User@Example.COM`）注册返回 `code=101 邮箱校验失败` |
| 根因 | `RegexUtil.java:31` 正则仅允许 `[a-z0-9]` |
| 修复 | 正则放开为 `[a-zA-Z0-9]`（local-part 与域名均支持大小写） |
| 回归 | 用例由 FAILED → PASSED；且验证新账号可正常登录 |
| 反向验证 | ✅ 正则改回小写后该用例如实失败 |

### BUG-005（P2）请求解析异常未处理 → 500 + 内部签名泄露

| 项 | 内容 |
|---|---|
| 现象（实测原文） | `JSON parse error: Cannot deserialize value of type 'org.example.lottery_system.controller.param.UserPasswordLoginParam' from Array value`<br>`Required request body is missing: public org.example...UserController.userPasswordLogin(...)`<br>`Content-Type 'text/plain;charset=UTF-8' is not supported` |

| 回归 | 8 条用例 FAILED → PASSED |
| 反向验证 | ✅ 通过分页越界路径验证兜底分支仍可被检测 |

## 3. 已消除缺陷（依赖侧）

### BUG-001（P2，已消除）MQ 不可达时无快速失败

| 项 | 内容 |
|---|---|
| 现象 | `POST /draw/prize` 在原 RabbitMQ（`8.136.222.102:5672`，阿里云）不可达时阻塞约 30s 后超时 |
| 影响 | MQ 抖动时抽奖接口长时间挂起，存在 Tomcat 线程耗尽风险 |
| 根因链（2026-10-11 查清） | ① 原阿里云实例**已释放**（`8.136.222.102` 连 ping 都不通，5672/22/80 全端口不可达）；② 迁移后的新实例 `172.24.62.152` 是 **VPC 私网地址**，公网不可达；③ 本机重装 RabbitMQ 时又遇到 **中文主机名导致节点名非法**（`COMPUTERNAME=蛟龙15K` → `rabbit@蛟龙15K` 含非 ASCII，Erlang 拒绝），`rabbitmqctl` 全部 `:badarg` |
| 处置（已消除） | ① 配置改为 `${RABBITMQ_HOST:localhost}`（可用环境变量覆盖，换地址不用改代码）；② 本机部署 RabbitMQ 3.13.7 + Erlang/OTP 26，节点名固定 `rabbit@localhost`（`RABBITMQ_NODENAME`，系统级+用户级均已设置）；③ 装为 Windows 服务 `RabbitMQ`（Running / 自动启动） |
| 验证（实测） | 抽奖接口 `POST /draw/prize` → `HTTP=200 code=200`，**耗时 0.0s**（原为阻塞 30s）；应用启动日志中 `Connection timed out` = 0、`Failed to check/redeclare` = 0 |
| 用例改判 | 原 `test_12::test_draw_prize_fails_fast_when_mq_unreachable`（xfail）→ 重写为 **`test_draw_prize_succeeds_fast_when_mq_available`**：MQ 可用时断言 `code=200` 且**耗时 ≤5s**（保留"依赖异常不得阻塞请求线程"的回归防线）；MQ 不可达时断言快速失败 |
| 回归结果 | pytest **242 passed / 0 xfailed**（MQ 恢复 152 → 10-16 补齐 195 → 10-20 人员详情 205 → 同日存量缺口补齐 **242**） |
| 教训 | 该缺陷长期被归类为"环境依赖待修"，实际根因是**网络路径变更 + 本机环境配置**，而非代码缺陷 —— 排查时先做连通性分层验证（ping / 端口 / 控制面），不要先归因版本或代码 |
